# 真实文本里会出现的语法：报道框架

Author/self-review: DSH agent session, 2026-09-22. Direction: Mingli Yuan.

这是既定三步的第 ② 步：给关系层一个**在真实文本中确实会出现**的语法，使语料落地门槛
（G5）有可达成的路径。第 ③ 步（重评 32 条上限与投影策略）尚未开始。

## 为什么原来的语法不行

原受控句式（`「A」授「B」「T」`）是为实验自造的，在 `data/corpus` 的 8208 段中命中
**0** 段。后果不是「覆盖率低」，而是**从它学到的任何东西都无法用真实文本检验**——
闭环根本不存在。所以第 ② 步要的不是「更多句式」，而是一个**可被真实文本证伪**的语法。

## 新语法：报道框架

```
<实体> <框架动词> <实体> 曰：「<引语>」
```

四个构式，各自独立取证（每个构式必须用自己的证据挣得角色映射）：

| 构式 | 框架 | 语料命中段数 |
|---|---|---:|
| `wei-quote` | `A謂B曰：「S」` | 144 |
| `wen-quote` | `A問B曰：「S」` | 182 |
| `gao-quote` | `A告B曰：「S」` | 28 |
| `yu-quote` | `A語B曰：「S」` | 13 |

声明读法（**声明**，随后由监督证据钉死；若证据与之矛盾，证据赢）：
`slot0 → agent（说话者）`、`slot1 → recipient（受话者）`、`slot2 → theme（引语）`。

## 切分：这次不能靠 `「」` 兜底

原语法用 `「」` 把**每一个**槽都围起来，切分是免费的。真实文本不会给这个便利，
所以槽边界必须写成**声明的规则**并测量其失败率：

- `slot0`：框架动词左侧的极大无标点串（不含 `，。；：「」？！、`），长度 1..10
- `slot1`：框架动词右侧、`曰` 左侧的同规则串
- `slot2`：`曰` 右侧 `「…」` 的内容，长度 1..300

实测槽跨度中位数 2、最大 9，故 1..10 的上界够用。

## 实测可行性（`node tools/grammar/measure.mjs`）

| 指标 | 值 |
|---|---:|
| 语料段落 | 8208（最长 1617 字） |
| **REACH（唯一解析）** | **367（4.47%）** |
| 同段多命中（歧义，返回 Unknown 而非任选） | 32 |
| 超长被排除 | **0**（上限 2048 高于语料最长值） |
| **ANSWERABLE（有证据时）** | **367（4.47%）** |

逐部覆盖：韓非子 82、管子 67、莊子 65、墨子 44、列子 29、禮記 28、論語 20、荀子 16、
孟子 14、尚書 2。

G5 的门槛是 1%，本语法达到 **4.47%**，门槛现在**可达且已达成**；原语法仍是 0。
八个 corpus-derived 证据记录（每构式 2 条）全部可回查（`verifySources` 8/8），
且逐条带该篇的授权标签——这是知识仓库的「语料来源」路径**第一次被真正使用**。

REACH 与 ANSWERABLE 必须分开看：REACH 只依赖切分，**是上界**；ANSWERABLE 还要求每个
构式的角色映射被监督证据钉死。两者现在相等，是因为四个构式都已取证；
若新增一个未取证的构式，REACH 上升而 ANSWERABLE 不动。

## 最大的一块覆盖率：先立契约，后取

```
<A>曰：「<S>」     3102 段（37.79%）
```

这是单一最大的一块可得覆盖率，是原四个构式总和的近八倍。它一度被**测量并声明、
但刻意不使用**（契约旧字段 `measuredButNotAdmitted`），条件写得很清楚：

> 等一份单独的契约先说清「缺失的角色意味着什么」。

**那份契约现在写好了**，记于契约的 `missingRoleSemantics`，然后才纳入构式：

| 要点 | 内容 |
|---|---|
| null 的含义 | 构式**不表达**该角色。不是「受话人未知」，更不是「没有受话人」 |
| 单一真源 | `ROLES_FOR_CONSTRUCTION(id)` 声明每个构式表达哪些角色，调用方不得覆盖 |
| 标注规则 | 已表达的角色必须给非空跨度，未表达者必须为 null。给 `<A>曰：「<S>」` 编造受话人**被拒**；给 `<A>謂<B>曰` 留空受话人**也被拒** |
| 排列空间 | 构式的排列空间是**它自己角色集**的排列：两槽从 2 个候选起步，不是 6 个 |
| 断言范围 | recipient 为 null 的读数**断言了施事与主题，对受话人什么也没断言** |
| 答案规则 | 基于该读数的答案必须把未表达的角色**如实报为未表达**，不得从上下文/对话/别处补 |
| 比较规则 | null 永不等于某个值；带 null 的对永不构成 RoleReversal |
| 不得推断 | 若问的就是缺失的那个角色，答案对该角色是 Unknown——不是猜 |

动机问题因此被正面回答而不是绕过：**补一个受话人仍然只能是凭空发明，所以现在补的是
「不表达」这个如实的状态**，而不是一个角色值。

未纳入的两个帧（二槽 `謂曰`/`語曰`）留在 `admittedAfterContract.notAdmitted`，
理由是**实测**而非原则：其真实文本形式多被副词/助词占据（`厲聲謂曰`、`樅公相謂曰`、
`蓋其語曰`、`故諸儒爲之語曰`），无法取得可诚实陈述的施事标注。

## 纪律被复制，而不是共享

`relations.ts` **未作任何修改**，两个模块也不共享代码。这是刻意的：抽公共核心会改动
已评审 patch 的受验证模块，那次重构应当是它自己的一次受评审变更，而不是加语法时的副作用。

风险是两个副本会漂移。缓解措施是 `tools/grammar/selftest.mjs`：
把**两个模块**用同一批用例驱动，行为必须一致（当前 **9/9 通过**），
其中包括「都从 6 个排列起步」「一条监督证据都消除 5 个」「矛盾标注都判 Conflict 且不提交」
「燃料耗尽都不加约束」「越界输入都 Unknown」「矛盾证据集都抛错」。
契约的 `duplicationDebt` 记有建议：第 ③ 步评审上限与投影时，一并折成参数化核心。

## 用法

```sh
node tools/grammar/measure.mjs --write          # REACH / 歧义 / ANSWERABLE
node tools/grammar/seed-reporting.mjs           # 从真实语料取监督证据（幂等）
node tools/grammar/selftest.mjs                 # 两个模块纪律是否一致
node tools/dialogue/ask.mjs Q1 \
  --grammar wenyan.relations.reporting.v1 \
  --text '或謂孔子曰：「子奚不爲政？」'          # 真实语料，返回 agent=或 recipient=孔子
node tools/knowledge/readiness.mjs --write      # G5 现在 PASS
```

对话层已做成**语法感知**：同一句真实语料，用 reporting 语法问 Q1 得到
`agent=或, recipient=孔子, theme=子奚不爲政？`；用原语法问则是
`Unknown(outside-declared-grammar)`。

## 不声称

- **不是句法分析**：这是带声明边界规则的框架匹配，不是古汉语句法分析。
- **不是理解**：匹配到一个框架只说明文本有这个形状，不说明它是什么意思。
- 实体槽是无引号的连续串，**边界规则可能出错**；歧义率与跨度分布是测量后如实给出的，
  没有藏起来。
- REACH 是依赖切分的**上界**，不是准确率。
- 不声称「说话者/受话者/引语」这一读法是唯一正确的语言学分析：它是一项**声明约定**，
  由监督钉死，也**可被监督证伪**。
- 4.47% 是刻意的低覆盖：这个框架是因其**会出现**而被选中，不是因其高频。

## 构式清单与覆盖（2026-09 实测）

`relations-reporting.ts` 现声明 **7 个构式**，顺序即规则：**标记最全者优先，
与已占跨度重叠的匹配一律丢弃**。

| 构式 | 形式 | 表达的角色 | 单匹配覆盖 |
|---|---|---|---|
| `wei-quote` | `E謂E曰：「…」` | agent, recipient, theme | 329 |
| `wen-quote` | `E問E曰：「…」` | agent, recipient, theme | 75 |
| `gao-quote` | `E告E曰：「…」` | agent, recipient, theme | 84 |
| `yu-quote` | `E語E曰：「…」` | agent, recipient, theme | 57 |
| `wen-plain` | `E問曰：「…」` | agent, theme | 95 |
| `gao-plain` | `E告曰：「…」` | agent, theme | 43 |
| `yue-quote` | `E曰：「…」` | agent, theme | 8,043 |
| **合计** | | | **8,726（11.20%）** |

「表达的角色」是构式的**声明**：`recipient` 不在其中时，标注必须是 `null`，
填一个受话人会被 `replay` 拒绝（`validExpected`）。反之，三槽构式留空受话人同样被拒。

### 未声明的构式，以及为什么

二槽的 `謂曰` 与 `語曰` **故意不声明**。实测其真实文本形式多被副词/助词占据：
`厲聲謂曰`（agent 抓成「厲聲」）、`樅公相謂曰`（「樅公相」）、`蓋其語曰`（「蓋其」）、
`故諸儒爲之語曰`（「故諸儒爲之」）。把这些槽标为施事就是断言假命题。
**宁可少一个构式，不可多一条假标注。**

### 标注的可采纳性过滤

`seed-reporting.mjs` 不再是先到先得：它对将要写入的槽做**声明的**过滤
（助词/副词前缀与后缀、报道动词、介词性受话人），并报告拒绝率。
实测拒绝率：**1,002 / 8,726 = 11.48%** 的 agent 槽以助词/副词开头。

### 多匹配：规则已改，并给出理由与实测

**原规则**：一段含两处框架即返回 `Unknown`（`ambiguous-frame-occurrence`），不挑一个。
当时的代价是 2/399 段，可以忽略。

**实测改变了这个判断**：二槽帧让多框架段落从罕见变常见，被放弃的是 **8,323 段（10.69%）**。
一段同时写着「子曰…」和「王曰…」的文本**陈述了两个关系**；拒绝读其中任何一个并不更诚实，
只是信息更少。因此改为：

> 读**标记最全**的那一帧（帧已按标记数量排序），并在读数里报告其余帧的**数量**
> （`additionalMatches`）。不是猜一个，而是**有次序地取第一个，并把歧义如实写进读数**。

解除后可读段落 **8,726 → 16,679（11.20% → 21.42%）**。

### 「在语法内」的真正判据：replay 接受这条记录

原先只检查「认得构式」，而多匹配段落**仍会返回构式名**，于是它们进了核心；
`replay` 是全有全无，**一条**这样的记录就让整条语法抛错。这是 CAP-REVIEW §实测三
的失效从另一扇门重入。

真正的判据是 `labelIsConsistent(text, expected)`：语法能读该文本，**且标注与构式的
排列空间相容**。选取与计数都用它，`constructionOf` 只作分桶键。

### 门只查了一半，曾被漏掉

`REPORTING_PROBES` 原先只声明 4 个构式，于是新增的 3 个**根本没被 G2 检查**——
包括独占语料 20.57% 的 `yue-quote`。补入后 G2 报出全部 7 个
（二槽构式正确显示 `survivors=1/2`）。**声明清单漏项会让『缺席』空过检查。**
