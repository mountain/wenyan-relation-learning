# 六爻、三段论与可修订的情境读法 v0.1

2026-09-23。方向：苑明理；实现、有限验证与自审：Codex（OpenAI），通过苑明理账号提交。
范围是一个封闭、可枚举的研究版本。不是一般语义完备性，也不是永不停机证明。

## 1. 六位、配置、文本是不同对象

爻位按初、二、三、四、五、上编号 1..6；六位字符串自下而上，阴 0、阳 1。
三才配对 `κ=(1 2)(3 4)(5 6)` 与上下卦对应位置配对 `τ=(1 4)(2 5)(3 6)`
合成 `1-2-5-6-3-4-1` 交替六环。它是六个**位置**的图。
64 种阴阳配置及单爻变化构成六维立方体；它是**配置**的图，有 384 条有向单爻边。
允许六位任意子集同时变化，则有 4096 个本卦/变爻集合组合，包含空变化。

这是本项目的显式组合解释。传统配对依据见《周易正义》乾九二疏：
https://zh.wikisource.org/wiki/周易正義/01乾
不据此宣称三才等于三计算，或已建立 adva 六个原始词的语义对应。
`proper`、`central`、`oppositeAtCorrespondence` 是结构特征，不是吉凶或逻辑有效性。
`complement`、`reverse`、`exchange-trigrams` 分别执行逐位翻转、倒序、上下卦交换；无通用的“共轭”别名。

## 2. 原文索引与来源校验

`tools/changes/catalog.mjs` 读取现有 Zhouyi 语料，每个主经文块提取卦辞、六条爻辞与两条额外用辞。
支持既有文本里冒号或逗号分隔的爻题；不修改原字形和标点。用上下卦名称独立核对六位编码。
每条记录保留篇、段、页面修订号、完整段落 SHA-256、UTF-16 起止跨度及许可引用。
许可全文和站点默认许可保留在 catalog.provenance；新程序的许可不覆盖转录文本。

`checkCatalogSources` 从原语料重新构建后逐项比较。哈希是完整性证据，不是来源真实性证明。
纯 TS 的 `readChanges` 接受调用者提供的 catalog，只验证结构，明确返回
`sourceVerification: caller-supplied-catalog`。关系库的 CLI 自行从本地语料重建。
文言仓只接收这个数据接口，不复制古籍数据。

### 2.1 来源绑定为什么按证据校验，而不按文件字节

`data/corpus/works/zhouyi.json` 是**派生**产物：语料重新抽取会重写它的字节，即使被绑定的段落一字未动。
2026 年扩充语料（前三史、志怪传奇、经部与集部，共 50 部）时正是如此——该文件只有
`extraction.removed` 的记账字段形状改变，而 `潛龍勿用。` 仍在第 3 段的 16–21 位。

原先的绑定把**整文件 SHA-256** 当作必须相等的值，于是每次重建语料都会让 `learning.jsonl` 无法读取。
该日志是**哈希链式 append-only**（每事件的 `previous` 是前一事件的 `hash`），改绑只能重写全链、
从而销毁它存在的意义，所以「重算摘要」这条路是堵死的。

现在 `reference.license.corpusSha256` 按**漂移上报**处理：`replayLearning` 返回 `sourceDrift`，
`experiments/changes/evidence.json` 记录之（当前 3 条：`qian-wait`、`lu-act`、`qian-disagreement`）。
**证据本身仍然必须逐项相等**：段落哈希、UTF-16 跨度、页面修订号、篇段编号与正文文本；
任何一项改动依旧直接抛错。另外新增 `licenseSha256`（许可对象自身的摘要），
事件一旦声明它，许可变动即致命——旧事件没有这一项，故对它们而言许可只由上述漂移摘要间接约束，
这是本次的已知弱化，如实记于此。

兄弟模块 `tools/taixuan` 从未遇到此问题，因为它绑的是**冻结快照** `data/taixuan/source.json`。
两条路线都可用：冻结快照（强度最高，代价是语料更新后需重新冻结），
或按证据绑定（自动跟随语料，代价是整文件摘要降为可追溯信息）。本模块选后者。

`tools/context-learning/engine.mjs` 因此新增 `sourceBinding` 选项，默认 `'exact'`（冻结快照仍按字节校验），
`'evidence'` 为上述策略；重放 `changes` 日志的 parity 测试显式声明 `'evidence'`。

### 2.2 语料索引的静默丢失（已修）

`client.exists()` 曾以 API **回显的标题**作匹配。`zh` 站点会跟随重定向，于是唐詩三百首清单里的
`長干行之一` 回显为 `長干曲 (君家何處住)`、`送杜少府之任蜀州` 回显为 `杜少府之任蜀州`，
320 首中有 25 首被当成不存在，而 `missing` 却是空的——静默丢掉选集 8%。
现改为经 API 自身的 `normalized` / `redirects` 映射解析，并按调用方传入的标题回报。

`觀「乾」。` 返回卦的索引；`觀「乾」之初爻。` 返回原文、位置特征和显式单爻变换。
`观` 亦可。无定义的问题返回 Unknown，不用叙事分数替代语义。

## 3. 三段论的有限完全判定

编码 A=11、E=10、I=01、O=00；第一位为全称/特称，第二位为肯定/否定。
六爻依次存大、小、结论的量，以及大、小、结论的质，故初四、二五、三上各配成一个命题。
编码只表示式；格和存在假设必须保留。

| 格 | 大前提两项 | 小前提两项 | 结论 |
|---|---|---|---|
| 1 | M,P | S,M | S,P |
| 2 | P,M | S,M | S,P |
| 3 | M,P | M,S | S,P |
| 4 | P,M | M,S | S,P |

支持 `boolean`（项可空，论域非空）与 `terms-nonempty`（S、M、P 均非空）。
二者的各格有效式数分别为 4/4/4/3 与 6/6/6/6。后者是明确的现代集合语义契约，
不概括亚里士多德全部历史逻辑或模态三段论。

完全性理由：三个一元谓词把任何论域划成八个 Venn 原子区。A/E/I/O 只依赖每个区是否为空，
不依赖区内基数。把每个非空区缩成一个代表，保持全部相关命题真值。因此任何反模型都有
不超过八个元素的同型占据表示。穷举非空占据掩码 1..255 即是这个片段的完全判定。
`Valid` 附全覆盖计数；`Refuted` 附可直接复算的集合反模型；预算耗尽返回 `Unknown`。
fuel 单位是访问一个掩码，不包含载入/语法检查的宿主成本。

`凡「S」皆「P」`、`凡「S」皆非「P」`、`有「S」為「P」`、`有「S」非「P」`
分别表示 A/E/I/O，`为`亦可。三句之间用句号，第三句以“故”开头。
语法要求三个不同项名、固定大前提/小前提顺序，保留每个项的独立原文跨度。
这是一种独立的研究问句语法，不向文言编译器隐式添加新关键字。

## 4. 学习的最小完整循环

新事件日志 `knowledge/changes/learning.jsonl` 与原有关系/语义日志分开，不改变 Q6/Q7 契约。
所有事件必须有具名监督者、依据、前一事件哈希和完整事件哈希。当前写入器要求单写者；
多进程协作须在上层加锁。历史单调追加；活动证据和候选读法可以减少或撤回。

事件只有三类：

1. `profile`：固定任务名、标签字典和候选特征组；不同版本用不同 id。
2. `example`：一个卦象/爻位上的监督标签，来源为实际爻辞或明确的人工夹具。
3. `retract`：具名撤回一条旧标注并说明理由，原事件仍保留。

每个特征组导出一张部分表。例如 `[position]` 假设同一爻位具有同一标签，
`[position,polarity]` 允许阴阳区别，`[bits,position]` 保留全部卦境。
同一特征键收到不同标签时，该特征假设被反驳，返回两条具体反证。
只有每个存活假设都覆盖查询且标签一致，才返回 `CandidateReading`。
它始终注明监督与特征族的条件，不能升级成古文理解的事实。

同一完整情境收到相反标签时是 `Contested`，显示双方依据，不投票。
这类情境从规则归纳中具名留出；别处仍可工作，回答会列出所有留出分歧。
没有覆盖、假设不同意、全体假设被反驳或预算不足均返回 `Unknown`，原因分别保留。
预测 fuel 只计算“特征假设/活动例子”比较；日志读取与完整性校验不在此计数内。

当特征族被反驳，可以显式追加一个更细的 profile。只有任务名和标签字典完全一致，
旧标注才参与新版本。旧版本仍可重放；这是一种有限语言的可修订机制，不保证无限进步。

已保留的真实文本演示：

- 乾初九“潜龙勿用”被**本实验监督者**标为 wait。
- 粗规则把这个标签错误推广到履初九。
- 履初九“素履，往无咎”被标为 act，反驳两个粗特征假设。
- 加入完整卦境后可区分两条；无标注的新情境仍是 Unknown。
- 一条故意矛盾的演示标注被保留并撤回，验证局部分歧和历史可重放。

wait/act 是本轮有依据的声明读法，不是经文自动推出的标签，也不是学术共识。
另一个**人工几何夹具**用两个阴阳例子反驳“仅看爻位”，在其余 382 个情境上迁移成功。
这验证归纳实现；不构成 382 条爻辞的语义理解指标。

## 5. 执行与新增标注

```sh
node --max-old-space-size=256 tools/changes/selftest.mjs
node tools/changes/selftest.mjs --write
node tools/changes/ask.mjs text '觀「履」之初爻。'
node tools/changes/ask.mjs syllogism '凡「猫」皆「动物」。凡「狗」皆「动物」。故凡「狗」皆「猫」。'
node tools/changes/ask.mjs predict advice-context-v2 --store knowledge/changes/learning.jsonl --bits 111111 --position 1
node tools/changes/ask.mjs learn /path/to/event-input.json --store /path/to/session.jsonl
```

`learn` 的输入包含 `{id,payload,provenance:{by,basis}}`；事件哈希由工具生成。
profile 示例：

```json
{"id":"my-profile","payload":{"kind":"profile","profile":"my-profile","task":"my-declared-reading","labels":["wait","act"],"hypotheses":[["position"],["position","polarity"]]},"provenance":{"by":"填写监督者","basis":"填写任务、标签含义和验证依据"}}
```

corpus example 的 source 必须携带 catalog 中对应爻辞的完整 source 与 text，篡改或错配即拒绝。
只想检验机械行为时，使用 `source:{kind:"authored",note:"人工夹具的定义"}`，不可冒称古籍标注。

`--write` 重建 catalog、三段论表及本轮验证报告，向本轮学习日志幂等追加演示事件。
不更新原关系实验历史 evidence。日常只读检查无需 `--write`。

## 6. 本轮验证与下一步

`evidence.json` 固定实际源码摘要、运行时与计数。独立集合 oracle 校验 512 个逻辑契约，
不调用实现的命题判断函数；所有无效形式附反模型。另检查 256 个受控文本形式、4096 次变化往返、
384 个原文查询、篡改拒绝、局部分歧、版本扩展、撤证，以及显式开启前后旧 pipeline 字段相等。
两仓新增纯 TS 核心逐字相同。既有角色、证据、报道语法、对话、语义分歧测试分别回归。

下一步应增加由明理审定的跨卦情境标注，留出整卦来评估语义迁移，并比较较细规则是否只是记忆原文。
当前未建立六个 Adva 原始词与爻义的必然映射，没有把六环同构当成语义证明，也没有更改 adva。
