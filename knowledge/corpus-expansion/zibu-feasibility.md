## 1. 清單本身的第一個事實：668，不是 669

`Portal:典籍` 的 `==子==` 段（第 33–772 行）共 **668** 個主命名空間連結。
經 `client.exists()` 核驗，**加入簡繁變體解析前後差別很大**：

| 項目 | 修復前 | 修復後（實測） |
|---|---|---|
| 清單條目 | 668 | 668 |
| 頁面存在 | 533（79.8%） | **551（82.5%）** |
| 頁面缺失 | 135（20.2%） | **117（17.5%）** |
| 靠簡繁變體救回 | — | **18 部** |

### 1.1 變體解析：`converttitles=1`，不是 `variant=`

`client.exists()` 原先只用 `titles=` 直查，於是簡體標題一律報缺失。
媒體wiki 自帶兩種機制，實測結果相反：

- `converttitles=1` — **有效**（8 例中救回 5 例，全量 668 條中救回 18 部），
  並在 `query.converted` 回報映射；
- `variant=zh-hant` / `variant=zh-tw` — **無效**（8 例中 0 例），
  它轉換的是輸出顯示，不是查詢目標。

救回的 18 部（映射如實記錄，未做人工改寫）：

```
关尹子→關尹子   正统道藏→正統道藏   黄帝四经→黃帝四經   黄帝阴符经→黃帝陰符經
混元阳符经→混元陽符經   农政全书→農政全書   四元玉鉴→四元玉鑒   崇祯历书→崇禎曆書
古方八陣→古方八阵   五十六种書並序→五十六種書並序   蕉叶帕→蕉葉帕   鬼谷四友誌→鬼谷四友志
韓擒虎話本→韩擒虎话本   万花樓→萬花樓   明月臺→明月台   周朝祕史→周朝秘史
```

**轉換是雙向的**：`韓擒虎話本` 反而是繁→簡——站上該頁以簡體存目。
這說明不能假設「站上一律繁體」，只能依 API 回報的映射為準。

### 1.2 真正缺失的 117 部：不是一類東西

逐條看缺失清單，至少混了三類，**不宜一律記為「紅鏈」**：

1. **非作品頁**：`農學古籍概覽`、`中醫內科方劑索引`、`算经十书`、`歷代遊記選`、
   `楹聯叢話全編` —— 索引／概覽／叢編，本就不該按單部作品收。
2. **書法、茶、象棋類短篇或輯錄**：`孫過庭書譜及其釋文`、`論法書`、`散論`、
   `題跋一七六則`、`唐人詠茶詩`、`象棋指歸`、`桔中祕敘` —— 多為後人輯錄，作者與版本歸屬不清。
3. **20 世紀作品**：`洪憲宮闈豔史演義`、`宋代宮闈史`、`明代宮闈史`、`隋代宮闈史`、
   `廿年繁華夢`、`胡塗世界`、`御香縹緲錄`、`張文祥刺馬案` —— 授權問題見本目錄
   `licensing-20c.md`；用戶已決定**不收 20 世紀作品**。

因此「117 部缺失」不等於「117 部該補」，其中相當部分是**本就不該收**。


## 2. 分診方法（一次主頁面抓取即可判定）

對每一部只抓主頁面一次，按下列順序判類（實作見 `tools/corpus/lib/discover.mjs`）：

| 判定 | 條件 | 路由 |
|---|---|---|
| ① 重定向 | `resolvedTitle !== 請求標題` | 用 `resolvedTitle` 作前綴（聊齋誌異的教訓） |
| ② 版本頁 | `{{versions}}` / `{{版本}}` / `{{disambig}}` | **人工選定版本**，不可自動 |
| ③ 子頁目錄 | `[[…/…]]` 子頁連結 ≥ 3 | `mainPageLinks`；若為 `/卷N` 相對形式亦已支援 |
| ④ 單頁分章 | `^==` 標題 ≥ 3 且無子頁 | `single`（標題即章） |
| ⑤ 其他 | 主頁 < 2KB 且子頁 0–2 | **人工分診**：殘篇、輯佚、消歧、僅存序跋 |

### 外推（明示為外推，且重尾故給區間）

樣本 14 部子頁路由作品的子頁數：33、46、157、17、528、16、53、13、8、11、101、13、240、31
→ 合計 1,267，**均值 90.5，中位數 27**。

- 若 58% × 533 ≈ **309 部**走子頁路由：
  - 按**中位數** 27 頁／部 → 約 **8,300 頁** → 約 **2,500 萬字**（現有語料 1,129 萬字的 2.2 倍）
  - 按**均值** 90.5 頁／部 → 約 **28,000 頁** → 約 **8,400 萬字**（7.4 倍）
- 抓取成本：`WikiClient` 節流 350 ms／請求 → 8,300 頁約 **50 分鐘**，28,000 頁約 **2.8 小時**，
  另加重試。快取可續跑，故中斷不致命。

**區間之所以寬達 3 倍，是因為 施公案／濟公全傳 這類數百回長篇主導了均值。**
因此建議先把**無重尾的子類**（儒家類、雜家類、術數類短篇）落庫，
把小說類的數百回長篇單列為後續批次。

## 6. 建議的分批與驗收

1. **每批 ~30 部**，按子類分（避免重尾集中）。每批只做一次主頁面抓取做分診（約 30 次請求）。
2. 分診為 ③④ 的自動建置；①②⑤ 進 `knowledge/corpus-expansion/` 的人工清單，逐條寫明原因。
3. 每批後必跑：`corpus validate`、`corpus selftest`、`check-fixtures`，並確認**無 0 節作品**
   （建置器已有 `BUILT EMPTY` 警告，但歷史上有過「靜默建成空作品」的先例）。
4. 授權逐部記入 `works/*.json` 的 `license.pageTemplates`；無標籤者記為站點預設 CC BY-SA 4.0
   （見本目錄 `licensing-20c.md`）。
5. 每批更新 `data/corpus/manifest.json` 的彙總統計，並在 commit message 中寫明
   「新增 N 部 / 缺失 M 部 / 人工 M′ 部」。
